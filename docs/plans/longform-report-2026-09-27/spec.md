# 复盘长图：日报 + 周报设计方案

状态：**已确认，实施中**。编写：2026-09-27。第 10 节六项决定均按建议执行（2026-09-27 用户确认）。

参考：用户提供的"韭菜指数"日报（2026-09-24 上午版）与周报（2026-09-21～09-26），原图在 `E:\download\cankao`。参考图是版式与信息密度参考，不是已验证的公式或数据来源。

## 0. 目标与不做什么

**目标**：在现有十强复盘基础上，做出信息密度接近参考图的**日报长图**和**周报长图**，每个数字可复算、可点开核对，并能导出 PNG。

**不做**：

- 不做买卖、仓位、抄底、持股过节等任何操作建议；不给情景概率或走势预测。
- 不用主观判断给维度打分，不把小样本比例包装成精确整数。
- 不恢复 L1–L5 散户分级（见 [暂缓记录](../../DEFERRED_L1_L5.md)）。
- v1 不接新闻源、不做上午版、不接付费数据（Wind、通达信、NeoData）。

## 1. 设计原则

1. **可复算**：每个分数都有公式、输入和分母；同一份采集回放得到同一结果。
2. **缺失说原因**：数据不足显示"—"并注明原因（如"基线 8/20 天"），不降低门槛凑数。
3. **事实与解读分开**：数字由代码填入；模型只写定性文字，不能自己写数字。
4. **不给建议**：提示只描述"处在什么位置"，不说"该怎么做"。
5. **方法有版本**：新公式写入新的方法版本号，新旧快照不混在同一条曲线里比较。

## 2. 与参考图的差异

| 参考图的做法 | 本项目的做法 | 原因 |
|---|---|---|
| 六维分数"基于公开讨论的定性推导"（原图页脚） | 每维由公式从采集数据计算 | 可复算、可核对 |
| 维度只给配方，如"动摇度=焦虑恐慌词频×60%+放量下跌×40%" | 给出输入字段、分母、归一化方法和缺失规则（第 4 节） | 配方不足以复现 |
| 韭菜浓度 = L1+L2 占比，样本"各板块约 15–20 条发言" | 不做 L1–L5；第 6 维用现有"追涨表达（试验）"，附判断覆盖率 | 18 条样本估 33% 的 95% 置信区间约 ±22 个百分点 |
| 预警灯文案"别去了！""轮盘上，别重仓" | 拥挤提示，固定描述句，如"换手与恐慌表达同处本表高位" | 不构成操作建议 |
| 情景 A/B/C 概率、"反弹别追""建议持股过节" | 不做 | 预测和建议 |
| 上周预言"印证/部分印证" | 上周数字回顾：只列上周值与本周值 | 不评判预测对错 |
| 事件时间线（美债、财报、会谈） | v1 只写行情事实；事件需新闻源，列为可选阶段 | 防止模型编造事件 |
| 资金来源 Wind、通达信 | 新浪/东方财富/同花顺公开数据 | 已有、免费；口径差异在页面注明 |

## 3. 数据层

### 3.1 新增：涨停生态（东方财富涨停池）

2026-09-27 实测接口：`https://push2ex.eastmoney.com/{接口}?ut=7eea3edcaed734bea9cbfc24409ed989&dpt=wz.ztzt&Pageindex=0&pagesize=<n>&sort=<字段>&date=YYYYMMDD`

| 接口 | 含义 | 用到的字段 |
|---|---|---|
| `getTopicZTPool` | 收盘仍涨停 | `c` 代码、`n` 名称、`zdp` 涨跌幅、`amount` 成交额、`hs` 换手、`lbc` 连板数、`zbc` 炸板次数、`fbt`/`lbt` 首次/最后封板时间、`fund` 封单资金、`hybk` 行业、`zttj` 涨停统计（x 天 y 板） |
| `getTopicZBPool` | 盘中曾涨停、收盘未封住（炸板） | `c`、`n`、`zdp`、`ztp` 涨停价、`zbc` |
| `getTopicDTPool` | 收盘跌停 | `c`、`n`、`zdp`、`days` 连续跌停天数 |
| `getYesterdayZTPool` | 昨日涨停股今日表现 | `c`、`n`、`zdp` 今日涨跌幅、`ylbc` 昨日连板数 |

**历史窗口很短**：实测 09-04 起能取到，09-03 及以前返回 0，约为最近 15 个交易日。

- 09-16 至 09-24 的涨停数据**现在还能补采，约两三周后过期**，所以补采是第一项任务（见 tasks.md T0）。
- 实测值：09-21 至 09-24 涨停依次为 103、63、51、52，参考周报写的是 105、65、51、53，基本一致。差异可能来自取数时点，实现时核对。

**分页**：`pagesize` 取 200，按 `tc` 总数翻页，直到取满；取不满时标记 `complete: false`。

**存储**：

- 私有原始记录：`work/limit-observations/YYYY-MM-DD.json`；
- 公开摘要：`public/data/limit/daily/YYYY-MM-DD.json`，外加 `index.json`、`latest.json`。公开摘要只保留代码、名称、涨跌幅、连板数、炸板次数、行业，每天约 20–40KB。

### 3.2 新增：两融余额（全市场）

- 接口：`https://datacenter-web.eastmoney.com/api/data/v1/get?reportName=RPTA_RZRQ_LSHJ&columns=ALL&sortColumns=DIM_DATE&sortTypes=-1`。实测可用，字段 `DIM_DATE`、`RZYE` 融资余额、`RQYE` 融券余额、`RZJME` 融资净买入。

- **板块级两融**：本次试的 `RPTA_WEB_BKJYMXN` 参数不对，**待验证**。验证之前，拥挤度不含两融（见 4.3）。

- 复用现有腾讯日线接口（市场热度已在使用）。

### 3.5 已知缺口

09-16 至 09-24 没有社区和市场快照，**无法补回**。能补的只有涨停生态、指数和两融。因此：

- 9 月第三、四周只能生成"部分周报"：涨停生态、指数、两融。社区维度显示"本周未采集"。
- 第一份完整周报是 09-28～09-30 这一周（国庆前只有 3 个交易日），前提是这 3 天定时任务都成功。

## 4. 指标定义

除特别说明，"本表分位"指当天十强题材之间的分位，沿用现有规则：至少 5 个可比题材，并列取中位秩。

### 4.1 涨停生态（全市场，每日）

| 指标 | 公式 | 缺失 |
|---|---|---|
| 涨停家数 | 涨停池条数 | 未取满时显示下限并标注 |
| 跌停家数 | 跌停池条数 | 同上 |
| 炸板率 | 炸板池数 ÷（涨停池数 + 炸板池数）× 100% | 分母为 0 时"—" |
| 连板高度 | 涨停池 `lbc` 最大值，并列出该股 | 无涨停时"—" |
| 连板梯队 | 按 `lbc` 分组计数：1、2、3、4、5 板及以上 | — |
| 晋级率 | 昨日涨停池中今日仍在涨停池的数量 ÷ 昨日涨停数 | 昨日池不可得时"—" |
| 昨日涨停今日表现 | 昨日涨停池今日 `zdp` 的等权平均和中位数 | 同上 |
| 昨日连板今日表现 | `ylbc ≥ 2` 子集的等权平均 | 子集少于 3 只时"—" |

这些是描述统计，不设"冰点/主升"之类的阶段判断。

### 4.2 主线轮盘（每日）

- **当日主线**：当天十强题材中，成分股涨停家数最多的题材。并列时取题材涨幅更高者。成分用题材发现当天保存的成分表。
- **涨停集中度** = 主线题材成分中的涨停家数 ÷ 全市场涨停家数 × 100%。
  - 一只股票可能属于多个题材，所以各题材的集中度相加可以超过 100%。
  - **注意**：参考图的"浓度"是 L1+L2 散户占比，含义完全不同。本项目用"涨停集中度"这个名称，避免混淆。
- **周轮盘**：列出每个交易日的主线、集中度和当日红盘率；统计本周换了几次主线。

### 4.3 六维 v2（题材级，每日）

新方法版本 `report-dimensions-2.0`。每一维 0–100。

| 维度 | 公式 | 输入来源 | 缺失规则 |
|---|---|---|---|
| **热度** | 0.4 × 讨论度 + 0.6 × 资金面 | 讨论度 = 现有 `dimensions.discussion`；资金面 = 题材成交额的本表分位 | 任一项缺失则"—" |
| **扩散力** | 0.5 × 传播力 + 0.5 × 讨论升温 | 传播力 = 现有 `spread`；讨论升温 = 现有 `growth` | 同上 |
| **动摇度** | 0.6 × 恐慌表达分位 + 0.4 × 放量下跌分 | 恐慌表达率 = 现有 `panic`，转为本表分位；放量下跌分见下 | 同上 |
| **回补力** | 回补表达率的本表分位 | 回补表达 = 现有补仓表达，加新规则"卖早了、踏空、还能上车吗、回调接回"（排除否定、转述和历史） | 有效分析样本少于 20 条时"—" |
| **拥挤度** | 换手率的本表分位（即现有 `crowding`） | v2 不含两融；板块级两融验证后在 v2.1 加入 | 缺当日换手时"—" |
| **追涨表达（试验，第 6 维）** | 现有行为审计试验比例 | `expressionProfile.behaviorAudit` | 判断覆盖不足时"—"并显示覆盖率；**不计入总分** |

**放量下跌分**：题材当日下跌、且成交额比前一交易日放大时，取跌幅绝对值的本表分位；否则为 0。前一日成交额不可得时"—"。

**题材成交额**：现有日报的 `sectors[]` 没有直接保存成交额。

- 当日值取成分股当日成交额之和（题材发现已采集成分行情）；
- 前一日值取成分股前一交易日成交额之和（腾讯日线）；
- 两者都要求至少 90% 成分有值，否则"—"。
- 实现第一步先确认题材发现的采集记录里是否已有这两项；没有则在采集时补存。

**总分（试验）** = 0.30 × 热度 + 0.20 × 扩散力 + 0.20 × 动摇度 + 0.15 × 回补力 + 0.15 × 拥挤度。

- 权重沿用参考图公开的比例（待确认，见第 10 节）。
- 五维缺任意一维，总分"—"，并列出缺哪一维。
- 页面标注"试验组合，未经样本外校准；高分表示本表内相对热闹，不是买卖信号"。

**关于"本表分位"的局限**：十个题材互相排名，冷门的一天也一定有题材拿到高分。当某题材自身历史满 20 个交易日后，v3 改为和自身历史比较，届时另起方法版本。

### 4.4 形态标签（规则化、描述性）

阈值："高"指 ≥ 65，"低"指 ≤ 45。按表中顺序匹配第一条，都不满足时为"中性"。

| 本项目名称（建议） | 参考图名称 | 规则 | 页面说明句 |
|---|---|---|---|
| 高热高动摇 | 镰刀型 | 热度高且动摇度高 | 关注度和恐慌表达同时处于本表高位 |
| 扩散低动摇 | 风筝型 | 扩散力高且动摇度低 | 讨论在扩散，恐慌表达较少 |
| 动摇有回补 | 吸铁型 | 动摇度高且回补力高 | 恐慌与回补表达同时较多，分歧明显 |
| 降温 | 泄气型 | 热度比前一交易日下降 ≥ 10 且动摇度比前一交易日上升 | 热度回落、动摇上升 |
| 冷清 | 佛系 | 五维都 ≤ 45 | 各维度都处于本表低位 |

名称用哪一套待确认（第 10 节）。参考图的名称带有评价色彩（如"镰刀"），建议页面用中性名，方法说明里注明对应关系。

### 4.5 拥挤提示（替代"接盘侠预警灯"）

| 等级 | 条件 | 固定文案 |
|---|---|---|
| 红 | 拥挤度 ≥ 75 且动摇度 ≥ 65 | 换手与恐慌表达同处本表高位 |
| 黄 | 拥挤度 ≥ 60 或动摇度 ≥ 60 | 换手或恐慌表达偏高 |
| 绿 | 以上都不满足且两项都不缺 | 换手与恐慌表达都不突出 |
| 灰 | 任一项缺失 | 数据不足 |

文案只描述位置，不出现"别去""别重仓""安全"等字样。

### 4.6 周度指标

- **周定义**：同一 ISO 周内、按交易日历属于交易日的日子。例如 09-21～09-24 共 4 个交易日。
- **完整度**：当周交易日都有日报时为"完整"。至少有 max(3, 60% 交易日) 天时出周分，并列出缺哪几天。更少时只出市场部分。
- **周题材池**：当周所有进过日报十强的题材。题材身份按代码识别。
- **周题材分** = 该题材在出现各天的总分平均值，至少出现 2 天；各维度同样取平均。
- **周九强**：按周题材分排序取前 9，并列时出现天数多者优先。
- **环比**：和上一周同题材的周题材分相比。上周没有时标"新进"，上周缺数据时标"上周无数据"。
- **市场周序列**：每天的红盘率、成交额、涨停家数、炸板率和主线；日均成交额；四大指数周涨跌（本周最后一个交易日收盘 ÷ 上周最后一个交易日收盘 − 1）。
- **资金周累计**：各日行业主力净额相加，只加有数据的天，标注"n/总天数"。行业口径是新浪行业，与申万不同，页面注明。

### 4.7 锚点对比（替代"924 两周年面板"）

- `config/report-anchors.json` 配置锚点日期和名称，例如 `{"date": "2024-09-24", "name": "924 行情启动日"}`。
- 当日报日期是锚点的周年日时，展示四大指数从锚点前一交易日到今天的累计涨跌，以及两融余额的变化。
- 只展示可从日线和两融接口计算的数字；"全 A 个股中位数""翻倍股数量"需要全市场个股历史，v1 不做。

## 5. 叙事层

复用 `sentiment/market_reading.py` 的机制：模型只读取事实列表（每条有 `id`），输出每段文字及其引用的 `factIds`，代码校验引用是否存在。

**新增：数字占位符**

- 现状：提示词要求正文不写数字，因此文字比参考图空泛。
- 做法：允许模型写占位符 `{{f:事实id}}`，由代码替换成事实表里的原值，例如"红盘率从 {{f:upRate.d1}} 降到 {{f:upRate.d4}}"。
- 模型自己写出的数字仍然判为不合格，于是文字能像参考图一样带数字，又不会改写数字。

**段落**：

| 段落 | 日报 | 周报 | 长度上限 |
|---|---|---|---|
| 标题（一句） | ✓ | ✓ | 40 字 |
| 一句话看懂 | ✓ | ✓ | 150 字 |
| 核心结论（2–4 条） | — | ✓ | 每条 80 字 |
| 题材定性（每个题材一句） | ✓ | ✓ | 60 字 |
| 周总结 | — | ✓ | 250 字 |

**禁用表达**：别去、别追、重仓、轻仓、抄底、上车、持股过节、建议买入或卖出、概率、预判、必涨、必跌，以及"印证""兑现"这类对预测的评判。出现任何一个即判为不合格，改用模板文字（第 6.3 节）。

**没有 API Key 时**：全部段落用模板文字生成，页面照常显示。

**新闻源（可选阶段 P4）**：接入公开财经快讯后，事件作为带来源链接的事实进入事实表，模型只能引用、不能补充。是否做由用户决定。


### 6.3 模板文字（没有模型时）

- 日报标题："{日期}：红盘率 {x}%，涨停 {n} 家，主线 {主线题材}"。
- 题材定性："{题材}：{形态说明句}；拥挤提示{等级}"。
- 周报一句话："本周 {n} 个交易日，主线切换 {k} 次；红盘率 {首日}→{末日}，日均成交 {x} 亿。"

### 6.4 展示规则

- 红涨绿跌；分数色阶沿用现有冷热色带。颜色不单独表达含义，数值始终可见。
- 每个格子悬停或点开，显示公式、输入值、分母和数据日期。
- 缺失格子显示"—"，悬停显示原因。
- 宽度固定 1200px，适合导出长图；窄屏时改为单列。

## 7. 导出 PNG

现有"观察卡"导出是在画布上手工绘制，只适合单张卡片，不适合整页长图。两个方案待选：

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 引入 `html-to-image`（MIT，约 30KB） | 页面上一键导出 | 新增一个前端依赖 |
| B. 本机 Edge 无头截图脚本 `scripts/export_longform.ps1` | 不加依赖；截图忠实于浏览器渲染 | 只能在命令行导出；要先启动看板 |

建议 A。

## 11. 风险

- **东方财富接口变化或限流**：涨停池是非公开文档接口。失败时该模块显示"未取得"，其他模块照常。
- **本表分位的相对性**：见 4.3，页面必须写明。
- **题材成分每天变化**：周题材分是不同成分表的平均值。周报页面说明这一点，不做成分对齐。
- **模型文字质量**：有禁用词和数字校验兜底；质量主要取决于所用模型。
