### 值得学习的呈现

- 从市场到板块再到证据，读者有清晰阅读路径。
- 同时列出金额、价格变化、事件和表达，不依赖一个分数解释全部现象。
- 前几名展开深度卡片，其余压缩，信息密度高但有主次。
- 六维矩阵适合横向比较，跨日标签帮助看变化。
- 核心矛盾和条件情景把静态表格转成连续复盘。

### 不能从图片确认的部分

- 没有可复现的五支温度计、传播力、补仓力、拥挤度及韭菜分公式；不能判断是人工、模型还是两者共同产生。
- “讨论热度”的解释含成交额，不能据此确认其实际输入来自社区讨论。
- L1–L5 没有给样本数、抽样范围、未知类别或验证结果。正文也在“发言构成”和“投资者构成”之间切换，因此不能直接把百分比当作真实投资者经验比例。
- 主力字段属于来源定义的资金统计，图片本身也称为方向性判断；无法据此追踪同一笔钱从 A 板块移动到 B 板块。
- 三种情景概率没有展示校准记录；本项目应先实现条件观察。
- 54/52 只涨停的来源差异已由图片自己提示。我们要保存口径，不为对齐图片选其中一个数字。

## 2. 每类内容怎么获取

分为“已有真实接入”“文档确认的候选”“需要补采或验证”“必须自行计算”。下表中的新接口本轮只查文档，没有开通、安装或运行。

图中自行列出的来源包含东方财富妙想、通达信、WebSearch、财经媒体和股吧/雪球等公开讨论。这说明报告宣称汇总多类材料，但没有说明各字段到具体接口的对应关系。不能据此确认其后端采集或模型流程。若后续用户已有通达信或妙想的合法导出，可考虑增加本地导入；目前没有确认可供本项目使用的自动接口，不列为默认生产依赖。

| 数据类 | 可用路径 | 能得到什么 | 限制与实施决策 |
| --- | --- | --- | --- |
| 个股历史行情 | 已有腾讯报价/日线；候选 Tushare `daily` | 日线价格、涨跌、量额 | 已有接口仅在部分标的验证过；新供应商需实测单位、日期、停牌、北交所和盘后字段。[日线说明](https://tushare.pro/document/2?doc_id=27) |

| L1–L5、复盘和情景 | 本地标准化数据、文本规则、人审标注、可选语言模型 | 表达分类、证据摘要、条件推演 | 没有一个已确认的公共接口能直接提供真实散户等级；需要自己定义与验证 |

以上网页核查证明“文档描述存在”，不保证指定日期和账号环境可用。Tushare 的 `daily_basic`、板块资金、历史成分、涨跌停等具有不同积分要求，新闻又是单独权限，不能视为一个免费套餐。[权限总览](https://tushare.pro/document/1?doc_id=108)

免费路线：先复用已验证接口，加少量候选公开源及本地缓存；未能完整回溯的数据从现在开始积累。付费路线：只针对历史成分、稳定全量数据、新闻等已确认缺口评估服务，先试样本再决定，不承诺某一套餐能一次解决所有问题。

## 3. 建议的可计算字段

以下是本项目拟议定义，不是博主的公式，也不是本轮已生效的代码。

| 字段/模块 | 拟议计算方式 | 必须同时显示 |
| --- | --- | --- |
| 上涨率 | 有有效涨跌幅的股票中，上涨股票数 / 有效股票数 | 上涨/下跌/平盘/停牌/缺失数量、市场范围 |
| 赚钱效应 | 上涨率、中位涨跌、昨日涨停股今日正收益率分别展示 | 这是当日价格分布，不是投资者实际收益 |
| 成交与缩量 | 全范围去重股票成交额汇总、较前交易日变化、自身历史分位 | 元/亿元、是否沪深北、是否含盘后成交 |
| 封板率 | 同范围收盘封住涨停股票 / 当日曾触及涨停股票 | 触板集合、炸板口径；不能用涨停数 / 全市场股票数 |
| 连板与 N 天 M 板 | 连续有效交易日封板记录；滚动窗口内累计次数 | 连续与累计分开、停牌和新股处理 |
| 板块涨跌 | 优先来源板块指数；自定义篮子使用明示权重及日期成分 | 不把龙头涨幅当板块涨幅 |
| 热点排行 | 每日同步完整可得行业/概念目录，补新事件主题；行情活跃榜、社区关注榜、资金榜分开，重点由当日结果选取 | 无固定行业白名单；排序字段、候选覆盖、新进/离榜、前日名次、重叠主题和缺失情况 |
| 社区讨论 | 已观察去重账户、有效文本、账户数历史分位、相对历史中位数的异常关注与观察池份额；详见评分研究 | 作者去重、采样额度、完整性、来源；规模与相对升温分开 |
| 传播互动 | 可得阅读/回复/点赞量及两次采集之间的增量；跨平台各算各的 | 累计或增量、采集时间；一张事后快照不能还原盘中增量 |
| 新出现账户 | 固定历史观察期内未出现、今天出现的平台账户数及占比 | 只描述首次被观察到，历史不足则不出该比例 |
| 追涨/恐慌/补仓 | 语义证据支持的各类表达 / 对应可判断样本，询问和转述另列；实验行为热度再作历史分位 | 文本分母、账户分母、未知和覆盖；自述不等于已核实交易 |
| L1–L5 | 先提取有证据的表达特征，再验证多帖账户标签；每档账户数 / 全部有效可识别账户数，保留未知 | 标签标准、账户窗口、稳定性门槛、总人数和分类覆盖；不是实际经验鉴定 |
| 综合过热 | 比较等权基线、主成分及人工标注的有序模型；参数须用历史样本估计和留出验证 | 不声称复制博主韭菜分；不把模型自述信心当校准概率 |
| 交易拥挤代理 | 成交向少数个股集中程度、换手历史分位分别列出 | 既不等于持仓集中，也不自动等于危险 |
| 风格偏好 | 明确市值/市场分组的成交占比与相对历史变化 | 分组互斥与多重归属规则；不能从北交所涨幅推出交易者是新手 |
| 事件解读 | 结构化行情变化 + 相关事件 + 公开讨论引用 | 事实/来源说法/本项目推断分开；有证据仍不代表因果已证实 |
| 次日观察 | 情景、触发条件、确认指标、失效条件、事后是否出现 | 不以语言模型口头判断产生未经校准的数值概率 |

拟沿用 V4 的可比历史分位和缺失规则。若重定义时段、成员、来源或评分方法，另建版本；任何“升温”比较必须在两天共同可比的覆盖范围内进行。

## 4. 数据获取与复盘流程

```text
来源探测 → 保存带时点的采集
          ↓
行情 / 成分 / 社区 / 事件分别标准化
          ↓
校验日期、单位、缺失、重复和成员归属
          ↓
确定性计算市场事实、板块排名与表达比例
          ↓
提取每个重点的证据包
          ↓
模板或模型起草解读 → 数字/引用校验 → 日报草稿
          ↓
快照归档、页面展示、导出、下一交易日验证
```

快讯和社区输入不作为执行指令。语言模型只能读取必要匿名证据，不能自己修改采集规则、补造数字或开启外部服务。报告时间与源数据时间分开，以便用户识别晚到数据和后续修订。

## 5. 首次实现前需要实测的最小样本

- 日期：9 月 2 日和 9 月 4 日，加一个普通非热点交易日；另测休市、停牌、新股和来源无数据情形。两张参考只作需求案例，不能成为唯一校准样本。
- 范围：上证、深证、创业板、科创、北交所；至少一个多股行业和一个交叉概念。
- 核查字段：量额单位、前收盘复权口径、成交包含范围、涨停限制、历史成分、板块指数与成分聚合差异。
- 社区：标题/正文/回复分别记录可得比例、互动时点与分页截断；不能用人工挑选的“最热”例子衡量全量分类质量。
- 输出：来源可行性表、字段样本、缺失原因、预计请求量及费用依赖。该报告完成后再确定生产采集策略。
