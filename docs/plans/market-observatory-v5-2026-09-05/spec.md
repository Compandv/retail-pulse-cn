## 一、目标与判断

目标用户是希望在盘后快速理解市场状态、热点迁移、散户讨论和风险分歧的个人观察者。

参考图的优势是把行情、板块、事件、资金与社区表达组织成一份可读日报：读者可以顺着“发生了什么—哪些方向最活跃—为什么被关注—讨论者表达了什么—下一天该验证什么”逐层查看。我们应建设这条完整的信息链。

图片中的三个量需要分清：军工卡片的讨论度为 95，六维表中的“韭菜分”为 85，L1+L2 为 68%。三者并非同一个指标。V4 猪肉的成交活跃 95.2 也不能直接拿来对齐其中任何一个分数。

拟议 V5 的目标是增加可核对的信息量和可用的比较范围。社区热度、市场成交、资金方向与表达结构继续独立呈现；研究者可以看到分项、分母、变化、来源与原文。

## 三、产品结构

```text
盘后首页：日期 / 数据状态 / 全市场事实 / 今日重点
    ↓
板块观察：行情活跃榜 / 社区关注榜 / 资金方向榜 / 升降温
    ↓
板块详情：成分与行情 → 催化事件 → 资金 → 表达证据 → 昨今变化
    ↓
复盘日报：核心矛盾 → 次日观察条件 → 来源与口径 → 保存 / 导出
```

继续保留股票查询、历史、日历、证据筛选和本地问答。日报与工作看板共用同一份数据，避免另写一份独立数字。日报首页保持紧凑，详细论据可展开；导出时呈现适合长图阅读的完整顺序。

## 四、能力范围与数据原则

### 1. 全市场行情和动态板块范围

行情层接收个股、指数与交易状态，计算涨跌家数、上涨率、中位涨跌、成交额及前日变化；短线观察增加涨跌停、炸板、连板、昨日涨停股的当日表现。

“沪深两市成交额”和“沪深北 A 股成交额”分开，不把几个成分指数的成交额直接相加冒充全市场。涨停口径标明 ST、新股、北交所、无涨跌幅限制股票和停牌的处理。

板块主数据分为行业、概念、市场分组和自定义篮子。“北交所”属于市场分组，“PCB 涨价链”可能属于自定义主题，不能都当成互斥行业。保留多重归属，跨板块资金或账户数不直接相加。

每日更新数据源可覆盖的完整行业/概念目录和证券范围，成分随日期保存，个股与主题关系有出处。板块名不作为固定白名单；新增事件主题也有进入候选的路径。行情尽量覆盖全部成分；社区如只能采样，则显示被采样成分、采样规则和覆盖差异，不冒充行业全体。

### 2. 热点发现与社区统计采用不同层次

先用全量可得板块行情、涨停分布、新闻事件和平台热榜发现候选热点；社区主题可独立进入候选，不能只关注上涨方向。再按可回放的方案读取常规范围及新增热点的讨论。保留连续可比的观察样本，固定的是采样规则而不是热点名单；热点额外取正文不能被当成讨论量增长。

每天由当日数据重排，展示进榜、离榜、名次和分项变化。军工、PCB、猪肉等只作验证案例，不保证其出现在首页。高度重叠主题聚组展开，避免一条产业链占满榜单。

社区榜先显示观察到账户数、有效文本、来源热榜名次、昨日变化与自身历史分位。平台自带热榜注明原始口径；不将不同平台不透明的分数直接平均。没有完整共同样本时，不发布“全市场散户人数最多”结论。

增加“首次在本观察窗口出现的账户”和平台“新晋粉丝”等辅助指标，但分别命名：首次被本项目观察到不等于刚入市，新关注某股也不等于新手或已经买入。

### 3. 行情与事件驱动的板块卡片

每张卡片包含：范围和覆盖、板块涨跌与成交变化、领涨/领跌成分、涨停与连板、资金方向、近期催化、社区规模、表达构成、前日变化和风险分歧。

事件按政策、公司公告/财报、产业价格、行业需求、宏观与外部事件分类。记录事件发生时间、首次公开时间、项目采集时间和来源。新闻去重后关联到主题及公司；“市场将上涨归因于某事件”和“公告明确披露某事实”分别表达。

只有取得可靠分时或事件序列时才写“低开高走”“全天不回落”等盘中路径。日线高低价只能支持有限描述；没有盘中数据时不从收盘结果补写故事。

### 4. 先研究评分与标注，再改善语义分析

先完成三个独立目标的定义与离线对照：讨论关注、情绪化交易表达、表达中呈现的分析层次。研究文档区分论文原方法、参考材料可确认部分和本项目候选公式；权重或等级边界不能由单日截图分数反推后直接上线。

先补正文、楼层上下文、引用关系、作者在观察窗口内的多条发言；再对明确追买、询问、看涨期待、补仓、恐慌和否定进行规则加模型的结构化判断。模型只处理已取得文本，输出引用片段、判断和不确定性。

L1–L5 继续描述表达特征，保留未知和样本分母。文字复杂、使用术语或说对一次行情，都不足以证明投资经验。文本构成与账户构成分别统计，未经明确的账户聚合方法不把前者称为“人数占比”。

建立多日期、跨板块的人工标注集，先比较规则基线和候选模型，再决定发布哪些维度。预算、模型供应商与线上启用方式留待讨论；目前不要求用户开通服务。

### 5. 丰富评分，但保持各项含义

拟保留五个市场观察位置：成交活跃、赚钱效应、社区关注、恐慌/追涨结构、风格偏好。能用原始比例清楚表达的，优先展示比例；需要标准化的，展示历史分位；尚不能可靠量化的，显示基础事实与解释。

六维矩阵先研究讨论规模、互动传播、恐慌表达、补仓表达、交易拥挤代理及看涨/追涨结构。讨论分候选采用去重账户的可比历史分位，同时显示绝对规模和异常增长。图中的“韭菜分”没有已确认公式；本次先研究行为表达率、相对行为热度及多信号综合过热三者的关系，比较透明基线和由数据估计的模型，再决定是否发布综合分。

L1–L5 的表达标签规则与账户聚合方法分别验证，展示未知及分类覆盖率。没有足够历史或文本信息时保留未知；不能为凑成完整五档而推定等级。

图中“补仓力”对应的实际可观察量是补仓表达，而非账户现金；“拥挤”只能由成交集中度、换手或讨论集中度代理，不等于真实持仓拥挤。

### 6. 生成有依据的日报

程序先计算事实与结构化变化；模板或语言模型将其整理成摘要。每个重要数字指向快照字段，每个催化指向来源，推断显示依据与可能的反例。缺来源时减少内容或标记待核实，不能补造。

次日情景先写触发条件、确认信号和失效信号；不生成没有样本外校准的 50%/30%/20%。未来加入概率时，要有固定预测目标、发布时点、历史预测记录及校准评估。

候选范围以每日可获取的行业、概念及新主题为准，公示覆盖数量和缺口。参考图方向与猪肉保留为映射/轮动回归案例，既有 24 个观察对象仍可查询，但不限定榜单候选，也不预留排名。

## 六、非功能要求与架构约束

- 延续 Python 采集与现有 TypeScript/React 看板架构；增加清晰的数据层，避免把采集、指标和日报文案写成一套不可复用逻辑。
- 原始采集、标准化事实、计算指标和日报分开存储，能够使用同一输入重算、审查和修订。
- 逐项保留来源、交易日、统计范围、单位、截止时刻、采集时刻、覆盖率及方法版本；盘后补取历史数据不冒充当时已记录的实时快照。
- 采集失败、未更新、缺失、范围不支持分别显示；旧数据可用时保留并提示日期，不能用零或昨天数据冒充今天。
- 如从 V4 的 00:00–15:00 改为参考图的 09:30–15:00，则作为独立窗口，盘前讨论单列，历史基线不混用。新闻盘前催化可入日报，但须在事件时间线上明确区分。
- 私有原文、匿名关联键、标注集与模型记录不直接打包到公开页面；首页只载摘要，详情按需读取，防止板块扩展后快照和页面迅速膨胀。
- 数据源预算采用“免费优先、关键缺口再评估付费”的草案路线，等待用户偏好；文档已确认有接口不等于本地已经拥有权限或通过实测。
- 自动化尊重来源访问边界；正式接入前明确服务权限、更新时段与可展示内容。数据供应商和模型服务不会在本轮被开通。

## 七、不在本轮承诺范围

本轮不实现或发布新功能，不复制未经公开确认的公式，不购买数据或模型服务，不给真实投资者分等级，不识别实际持仓、机构身份或“聪明钱”，不以单日截图分数作为准确性目标。

完整评论历史、全平台用户画像、分钟级资金轨迹、预测概率和全球宏观自动因果分析不列为首期交付。
